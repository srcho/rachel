# 할 일 화면 레이아웃 개선

## 확인한 문제와 변경

- 기존 페이지는 화면 높이를 강제로 채우고 각 열에 별도 세로 스크롤을 두었다. 카드 7개로 확인한 1440×900 화면에서 열은 약 790px 높이였다. 이 조건에서 문서 자체의 세로 넘침은 재현되지 않았다.
- 820×720에서는 보드 내부 너비가 771px인데 콘텐츠 너비가 956px여서 가로 스크롤이 발생했다. 고정 최소 열 너비가 원인이었다.
- 페이지·보드·열의 고정 높이와 내부 스크롤을 제거했다. 열은 내용만큼 높아지고, 긴 목록은 문서 스크롤로 탐색한다. 좁은 보드는 2열, 1280px 이상은 4열이며 전체 최대 너비는 1440px다.
- 검색창은 데스크톱에서 폭을 제한하고 모바일에서는 별도 한 줄을 쓴다. 검색 지우기, 적용한 필터 수와 초기화, 상태별 추가 버튼을 제공한다.
- 빈 상태와 카드 안쪽 여백을 정돈했다. 모바일에서 선택한 상태에 검색 결과가 없을 때 안내가 빠지는 문제도 수정했다.
- 오늘 일정은 줄바꿈과 제목 말줄임으로 가로 넘침을 방지한다. 드래그로 할 일을 만드는 동작은 유지한다.

## 검증

로컬 Supabase의 전용 임시 사용자로 Chromium Playwright CLI에서 확인했다. 실제 사용자 데이터는 사용하지 않았다.

| 조건 | 결과 |
| --- | --- |
| 1440×900, 카드 7개 | 열 높이 136~159px, 가로·세로 내부 스크롤 없음 |
| 1024×768 / 820×720 | 2열 배치, 문서와 보드의 가로 넘침 없음 |
| 390×844, 모바일 목록·보드 | 내용에 맞는 높이, 가로 넘침 없음 |
| 320×568, 모바일 목록 | 실제 콘텐츠가 화면보다 길어 문서 스크롤 발생, 내부 스크롤 없음 |
| 320 / 390 / 820 / 1440px, 다크 모드 | 가로 넘침 없음, 화면 캡처 검토 |
| Todo에 카드 30개 추가 | 1440 / 820 / 390px에서 마지막 카드 접근 가능, 내부 세로 스크롤 0개 |
| 긴 제목의 오늘 일정 3개 | 320px에서 가로 넘침 없음, 일정 → Backlog 드래그 생성 성공 |
| 상태별 추가 → 검색 → 라벨 필터·초기화 → 드래그 → 새로고침 | 추가 대상 상태와 이동 결과 저장 확인 |
| 모바일 상태 필터의 결과 0개 | 빈 상태 안내 표시 |

- `pnpm typecheck`: 통과.
- `pnpm lint`: 오류 없음. 기존 경고 26개와 정보 4개는 변경하지 않았다. 변경한 5개 파일의 Biome 검사는 진단 없이 통과했다.
- `pnpm exec vitest run src/modules/tasks`: 8개 파일, 38개 테스트 통과.
- `pnpm build`: Next.js 및 Serwist 빌드 통과.
- 실기기 iOS PWA 터치 동작은 이번 검증에 포함하지 않았다.
