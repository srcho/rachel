## 1. 배경과 비전

### 1.1 문제

- 할 일(Trello), 일정(Google Calendar), 회의 기록(메모·녹음)이 각각 다른 앱에 흩어져 있다.
- 이들 사이의 연결이 없다. "이 할 일은 어느 회의에서 나왔지?", "지난달에 뭘 결정했지?"에 답하려면 앱 세 개를 뒤져야 한다.
- 기존 AI 비서는 매번 처음부터 설명해야 하고, 내 데이터를 직접 읽고 쓰지 못한다.

### 1.2 비전

**"내 하루의 데이터가 모이는 곳이자, 그것을 기억하고 대신 움직여 주는 비서."**

| 축 | 의미 |
|---|---|
| 모으기 (Collect) | 할 일·일정·회의 전사가 한 데이터베이스에 쌓인다. |
| 기억하기 (Remember) | 레이첼은 사실·선호·결정·사람을 기억하고 필요할 때 꺼낸다. |
| 움직이기 (Act) | 화면에서 손으로 할 수 있는 모든 일을 레이첼도 대화로 할 수 있다. |
| 되돌아보기 (Reflect) | 쌓인 데이터에서 매일·매주 인사이트를 뽑는다. |

### 1.3 목표 (v1)

| ID | 목표 | 측정 |
|---|---|---|
| G1 | 모바일에서 빠른 입력 | 할 일 추가 3초, 회의 녹음 시작 5초 이내 |
| G2 | 회의 후 즉시 정리 | 종료 후 2분 내 요약·액션 아이템 확인 |
| G3 | 대화로 모든 CRUD | 할 일·일정·회의·기억의 화면 액션 100%를 레이첼 도구로도 수행 가능 |
| G4 | 저비용 운영 | 월 운영비 ≤ $10 (인프라 $0 + 사용량), 회의 주 5시간 기준 |
| G5 | 확장 비용 0 | 새 모듈(예: 저널) 추가 시 코어 코드 수정 0줄 |
| G6 | 체감 성능 | 주요 화면 LCP ≤ 1.8s (모바일 4G), 인터랙션 ≤ 100ms 반응 |

### 1.4 비목표 (v1에서 하지 않는 것)

- **다중 사용자 협업**(공유 보드, 팀). 데이터 모델은 RLS로 대비하되 UI는 만들지 않는다.
- **앱 스토어 배포.** PWA로 충분한지 먼저 검증한다. iOS 제약이 치명적이면 Capacitor 셸을 검토한다.
- **온라인 화상회의 봇**(Zoom·Meet 참여). 오프라인 회의 전사에 집중한다.
- **음성 응답(TTS).** 비용·복잡도 대비 가치가 낮다. 추후 옵션.
- **이메일·슬랙·노션 연동.** 모듈 슬롯만 남긴다.

## 2. 설계 원칙

| # | 원칙 | 의미 | 구현 규칙 |
|---|---|---|---|
| P1 | **모듈이 곧 기능** | 기능 하나 = 폴더 하나 | 모든 기능은 `src/modules/<name>` 안에 닫혀 있다. 코어는 계약(interface)만 알고, 모듈 간 직접 import는 금지한다. 모듈은 이벤트와 도구로만 대화한다. |
| P2 | **UI 액션 = 에이전트 도구** | 사람이 할 수 있으면 레이첼도 할 수 있다 | 서비스 레이어 하나를 Server Action과 에이전트 도구가 공유한다. 도구 정의가 없는 기능은 미완성으로 본다. |
| P3 | **LLM은 마지막 수단** | 비용은 설계로 줄인다 | 집계·정렬·필터는 SQL. LLM 호출은 사용자 행동 1회당 최대 1회, 배치 결과는 캐시한다. |
| P4 | **조용하고 빠른 UI** | 미니멀·컴팩트·모던 | shadcn 기본형, 장식 없음, 낙관적 업데이트로 100ms 안에 반응. 로딩 스피너보다 이전 데이터 유지. |
| P5 | **투명한 기억** | 레이첼이 아는 것을 내가 본다 | 모든 기억은 출처(source)와 함께 저장되고, 화면에서 수정·삭제할 수 있다. |
| P6 | **안전한 자율성** | 생성은 자동, 파괴는 확인 | 도구마다 위험 등급(read/write/destructive). write는 즉시 실행 + 되돌리기, destructive는 확인 카드. |
| P7 | **내 데이터는 내 것** | 잠금 없음 | 전체 내보내기, 주간 자동 백업, 회의 오디오는 내 기기에 보관(v1). 서버에는 텍스트만. |

## 3. 사용자와 핵심 시나리오

### 3.1 사용자

- **단일 사용자**(Vincent). 주 기기는 iPhone(홈 화면에 설치한 PWA)과 macOS 데스크톱 브라우저.
- 한국어 UI. 회의는 한국어이며 영어 용어가 섞인다. 레이첼과는 친근한 존댓말(해요체)로 대화한다.
- 하루 패턴: 아침 브리핑(1분) → 수시 할 일·채팅(10회 안팎) → 회의 전사(주 3~5회) → 저녁 정리 → 일요일 주간 리뷰.

### 3.2 핵심 시나리오

이 여섯 장면이 수용 기준의 기준점이다.

| ID | 장면 | 흐름 |
|---|---|---|
| S1 | 아침 | Today 화면을 열면 오늘 일정, 마감 할 일, 어제 미완료, 레이첼의 브리핑이 한 화면에 있다. |
| S2 | 회의 | 캘린더의 "주간 싱크"가 임박하면 Today에 "녹음 시작" 버튼이 뜬다 → 탭 → 실시간 전사가 흐른다 → 종료 → 2분 안에 요약과 액션 아이템 제안 → 체크해서 칸반에 추가. |
| S3 | 대화형 CRUD | 칸반 화면에서 FAB 탭 → "이 보드에서 마감 지난 것 다 다음 주 월요일로 옮겨줘" → 확인 카드 → 실행 → 30초 안에 되돌리기 가능. |
| S4 | 기억 | "지난번에 김OO이랑 얘기한 예산 얼마였지?" → 회의 전사 검색 + 기억 → 근거(회의 링크)와 함께 답한다. |
| S5 | 주간 리뷰 | 일요일 저녁 알림 → Insights에서 완료율·회의 시간·미루기 패턴과 레이첼의 한 문단 리뷰를 본다. |
| S6 | 캡처 | 길에서 떠오른 생각을 공유 시트나 음성으로 던지면 레이첼이 할 일·일정·기억으로 분류해 제안한다. |

## 4. 범위: 모듈 맵

```
core        앱 셸 · 인증 · 모듈 레지스트리 · 이벤트 버스 · 잡 큐 · 설정 · 디자인 시스템
tasks       칸반 보드/컬럼/카드                              M1  Must
calendar    Google Calendar 연동 · 미러 · CRUD               M2  Must
meetings    녹음 · 근실시간 전사 · 화자 분리 · 요약            M3  Must
agent       레이첼 채팅(floating) · 도구 실행 · 컨텍스트 조립  M4  Must
memory      의미 기억 · 검색 인덱스 · 기억 관리 화면           M5  Must
insights    Today 브리핑 · 주간 리뷰 · 대시보드 위젯           M6  Must
capture     빠른 캡처 인박스 · Share Target                   M7  Should (제안)
notify      웹 푸시 · 리마인더                                M8  Could
```

우선순위는 MoSCoW(Must / Should / Could / Won't)로 표기한다. 모듈 간 의존은 **이벤트와 도구**로만 허용한다. 예를 들어 meetings 모듈은 tasks 모듈을 import하지 않고, "액션 아이템 제안"을 요약에 담아 두면 사용자가 확정할 때 tasks 서비스가 호출된다.

## 5. 기능 요구사항

각 모듈은 **목적 → 유저 스토리 → 요구사항 → 레이첼 도구 → 수용 기준 → UI 노트** 순으로 적는다. 요구사항 ID는 모듈 접두어를 쓴다(T-1, CA-2…).

### 5.0 Core

| ID | 요구사항 | 우선순위 |
|---|---|---|
| C-1 | **인증.** Supabase Auth, Google 로그인 기본. 세션은 `@supabase/ssr` 쿠키. 미인증 접근은 `proxy.ts`에서 차단. | Must |
| C-2 | **앱 셸.** 모바일: 하단 탭 5개(Today · Tasks · Calendar · Meetings · More) + 중앙 FAB(레이첼). 데스크톱: 좌측 아이콘 레일 + 본문 + 우측 채팅 패널. | Must |
| C-3 | **모듈 레지스트리.** 모듈이 nav·routes·tools·widgets·jobs·indexers·commands를 선언하면 코어가 조립한다. `modules/index.ts`에 한 줄 추가가 기능 추가의 전부다. | Must |
| C-4 | **이벤트 버스 + 잡 큐.** 도메인 이벤트를 기록하고, 비동기 작업은 `jobs` 테이블에 넣어 1분 주기(pg_cron)와 즉시 킥으로 처리한다. | Must |
| C-5 | **PWA.** 설치 가능, 오프라인 셸, 앱 바로가기(새 할 일 · 녹음 · 채팅), 상태바·세이프에어리어 대응. | Must |
| C-6 | **설정.** 프로필·타임존·테마·연동·전사 모드·오디오 보관·비용 미터·데이터 내보내기. | Must |
| C-7 | **테마.** 라이트/다크/시스템. | Must |
| C-8 | **커맨드 팔레트(⌘K).** 모듈이 등록한 명령 + 전역 검색. | Should |
| C-9 | **비용 원장.** 모든 LLM·임베딩·전사 호출의 사용량(토큰·오디오 초)과 단가표로 산출한 비용을 `llm_usage`에 기록한다. 대시보드(Insights)와 설정에서 월 누적·기능별·모델별·일별 비용을 보여 주고, 채팅 응답·회의·브리핑 등 **결과 옆에 개별 비용**을 표시한다. 월 예산은 선택 사항(미설정이면 표시만). | Must |

### 5.1 Tasks (칸반)

**목적** — 트렐로처럼 가볍고, 트렐로보다 빠르게.

**유저 스토리**
- 엄지 하나로 할 일을 추가하고 컬럼을 옮기고 싶다.
- 마감·우선순위·라벨로 "오늘 할 것"을 바로 보고 싶다.
- 회의에서 나온 액션 아이템이 (내 확인 후) 자동으로 카드가 되면 좋겠다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| T-1 | 보드·컬럼·카드 CRUD. 첫 로그인 시 기본 보드 "Personal"과 컬럼(Backlog · Todo · Doing · Done) 자동 생성. | Must |
| T-2 | 드래그앤드롭(컬럼 간·컬럼 내), 키보드 이동, 모바일 롱프레스. 순서는 fractional index로 저장해 이동 시 1행만 갱신. | Must |
| T-3 | 카드 속성: 제목, 설명(markdown), 마감(날짜 또는 일시), 우선순위(P0~P3), 라벨(텍스트+색), 체크리스트, 출처(수동/레이첼/회의/캡처), 연결(일정·회의). | Must |
| T-4 | 빠른 추가: 컬럼 하단 인라인 입력. 자연어 마감("내일 3시", "다음 주 월")은 로컬 파서(chrono 계열) 우선, 실패 시에만 LLM. | Should |
| T-5 | 필터·뷰: 오늘 마감, 지연, 우선순위, 라벨. 저장된 뷰는 v2. | Should |
| T-6 | 완료 처리: Done 컬럼 이동 = `completed_at` 기록(지표용). 아카이브·복구. | Must |
| T-7 | 다중 기기 실시간 동기화(Supabase Realtime). 낙관적 업데이트, 충돌은 last-write-wins. | Must |
| T-8 | 오프라인: 읽기 캐시(Must). 쓰기 아웃박스는 P6(Could). | Must/Could |
| T-9 | 반복 할 일. | Could |

**레이첼 도구** — `tasks.list(filter)`, `tasks.get`, `tasks.create`, `tasks.update`, `tasks.move`, `tasks.complete`, `tasks.delete`(destructive), `tasks.bulkUpdate`(destructive), `boards.list`

**수용 기준**
- 카드 이동 후 100ms 내 UI 반영. 실패 시 롤백 + 토스트.
- 카드 100장 보드에서 모바일 중급기 스크롤 60fps.
- "다음 주 월요일까지 PRD 검토" 입력 → 마감이 정확히 파싱된 카드 생성.
- 레이첼에게 "Doing에서 마감 지난 것 보여줘" → 정확한 목록과 카드 링크.

**UI 노트** — 컬럼은 모바일에서 가로 스크롤 + 스냅. 카드는 제목 2줄 제한, 마감은 상대 표기(D-2 · 오늘 15:00), 색은 우선순위 점 하나만. 카드 상세는 바텀시트(모바일)/사이드시트(데스크톱).

### 5.2 Calendar

**목적** — Google Calendar를 진실 원천(source of truth)으로 두고, 앱 안에서 보고 고치며 레이첼이 다룬다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| CA-1 | Google 연동. 로그인과 **별도의 OAuth 흐름**(오프라인 액세스, `calendar.events` + `calendar.readonly`). 동기화할 캘린더 선택. | Must |
| CA-2 | 증분 동기화(`syncToken`). 트리거: 앱 열 때(마지막 동기화 5분 경과 시), 15분 주기 잡, 쓰기 직후. 로컬 미러 테이블에 보관. | Must |
| CA-3 | 일정 CRUD: 제목·시간·종일·위치·설명·참석자(읽기). Google에 write-through, 실패 시 `pending_push`로 재시도. | Must |
| CA-4 | 뷰: 아젠다(모바일 기본), 주간(데스크톱 기본), 월간. | Must |
| CA-5 | 회의 연결: 진행 중·임박(±10분) 일정에 "녹음 시작" 진입점. 회의 레코드에 일정 링크. | Must |
| CA-6 | 할 일 ↔ 일정: 카드에서 시간 블록 만들기("이 카드 내일 오전에 2시간 잡아줘"). | Should |
| CA-7 | 반복 일정: 인스턴스 단위 표시(`singleEvents=true`). 편집은 "이 일정만"이 v1, 시리즈 편집은 v2. | Should |
| CA-8 | Google push 알림(watch 채널)로 즉시 동기화. | Could |

**레이첼 도구** — `calendar.listEvents(range)`, `calendar.getEvent`, `calendar.createEvent`, `calendar.updateEvent`, `calendar.deleteEvent`(destructive), `calendar.findFreeSlots(range, duration)`

**수용 기준**
- Google에서 바꾼 일정이 앱을 열면 즉시, 닫혀 있어도 15분 내 반영.
- 앱에서 만든 일정이 5초 내 Google에 표시.
- 토큰 만료·권한 회수 시 "다시 연결" 안내가 명확하고 한 번의 탭으로 복구.

**UI 노트** — 아젠다는 날짜 헤더가 sticky, 현재 시각 라인. 일정 카드는 시간·제목·위치 한 줄. 색은 캘린더 색을 좌측 바로만.

### 5.3 Meetings

**목적** — 오프라인 회의를 녹음하면 전사가 실시간으로 흐르고, 끝나면 요약·결정·액션 아이템이 정리되어 저장·검색·기억된다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| M-1 | 녹음: 마이크 권한, 시작·일시정지·종료, 경과 시간, 입력 레벨 미터, 화면 꺼짐 방지(Wake Lock), 백그라운드 진입 경고. | Must |
| M-2 | **근실시간 전사 — 라이브 패스.** 브라우저가 16kHz mono PCM을 무음 경계에서 8~20초 WAV 세그먼트로 잘라 서버 라우트로 보내고, 서버가 Meta `muse-voice-transcribe-1.0` 배치 엔드포인트(ENDPOINTING 모드, 언어 바이어스 한국어·영어, 키워드 힌트)로 전사해 화면에 누적. 지연 목표 ≤ 30초. 화자 라벨은 없다. | Must |
| M-3 | **정식 전사 — 파이널 패스.** 종료 후 기기에 보관된 PCM 세그먼트를 9.5분 청크(30초 겹침)로 이어 붙여 DIARIZATION 모드로 재전사하고, 겹침 구간으로 청크 간 화자 라벨을 이어 붙인다(스티칭). 결과가 정식 전사가 되어 라이브 패스 텍스트를 대체하고, 요약을 화자 반영 버전으로 갱신한다. 기본 켬, 회의별 끌 수 있음. | Must |
| M-4 | 세그먼트 즉시 저장. 앱이 죽어도 이미 전사된 부분은 남는다. 오프라인 세그먼트는 로컬 큐 후 재전송. | Must |
| M-5 | 종료 후 후처리(잡): 전사 정리(문장부호·필러 제거·용어 교정) → 구조화 요약(TL;DR · 핵심 포인트 · 결정 · 액션 아이템(담당·기한) · 열린 질문 · 참석자 추정) → 기억 추출 → 검색 인덱싱. 목표 2분. | Must |
| M-6 | 리뷰 시트: 제안된 액션 아이템을 체크해 카드 생성(기본 전체 선택). 팔로업 일정 제안도 함께. | Must |
| M-7 | 회의 상세: 요약, 타임스탬프 전사, 연결된 카드·일정, "이 회의에 대해 물어보기"(범위 지정 RAG). | Must |
| M-8 | 회의 중 "중요" 마킹: 타임스탬프 북마크 → 요약에 가중. | Should |
| M-9 | **오디오 보관(v1: 내 기기).** 압축 녹음(MediaRecorder, opus 또는 aac)을 IndexedDB에 보관해 회의 상세에서 재생·구간 이동. PCM 세그먼트는 파이널 패스 후 삭제. 다른 기기에서는 오디오 없음(텍스트만). Supabase Storage 업로드는 v1.5 옵션. | Must |
| M-10 | **화자 이름 붙이기.** 파이널 패스의 화자(화자 1·2…)에 이름을 붙이면 회의 전체와 요약에 반영되고 기억(person)과 연결된다. 캘린더 참석자를 이름 후보로 제안. | Should |
| M-11 | 전사 힌트: 캘린더 참석자 이름, 최근 카드 제목, 사용자 사전 → 전사 `prompt`/`keywords`, 언어 힌트(ko, en). | Should |
| M-12 | 회의 템플릿(1:1 · 스탠드업 · 인터뷰)에 따른 요약 포맷. | Could |
| M-13 | **진짜 실시간 모드.** Meta Realtime WebSocket은 핸드셰이크에 API 키가 들어가 브라우저 직결이 불가하고, 세션 60분·실시간 페이싱 제약이 있어 서버 relay가 필요하다. Vercel 함수 시간 제한 때문에 v1에서 제외. v2에서 relay 스파이크. | Won't (v1) |

**레이첼 도구** — `meetings.list`, `meetings.get`, `meetings.search(query, range)`, `meetings.summarize(id, force)`, `meetings.createTasksFromActionItems(id, itemIds)`, `meetings.delete`(destructive)

**수용 기준**
- 60분 회의에서 전사 실패 세그먼트 ≤ 1개. 실패 세그먼트는 표시되고 재시도 가능.
- 종료 → 요약 완료 2분 이내(60분 회의 기준).
- 액션 아이템 → 카드 생성이 2탭.
- 60분 회의 전사 비용 ≤ $0.40(라이브 패스 $0.18 + 파이널 패스 $0.18 + 요약), 회의 상세에 항목별로 표시.

**UI 노트** — 라이브 화면은 큰 타이머 + 흐르는 전사(문장 단위, 화자 없음) + 하단 "종료" 하나. 종료 후 "정리 중… (화자 분리 3/7)" 진행 상태를 목록과 상세에 표시하고, 완료되면(P5 이후) 푸시. 전사 화면은 폰트 크기 조절 가능. 재생은 같은 기기에서만.

### 5.4 Agent (Rachel)

**목적** — 어떤 화면에서든 한 탭으로 열리는 비서. 내 데이터를 읽고 쓰고 기억한다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| A-1 | **플로팅 진입점.** 모바일: 하단 중앙 FAB → 바텀시트(반/전체, 드래그). 데스크톱: 우측 패널(토글·너비 조절·고정), 단축키 ⌘J. 라우팅해도 대화 상태 유지. | Must |
| A-2 | 스트리밍 응답, 도구 호출 카드(입력·결과·되돌리기 버튼), 진행 표시. | Must |
| A-3 | **화면 컨텍스트 주입.** 현재 라우트와 선택된 엔티티(보드·회의·카드)를 "컨텍스트 칩"으로 보여 주고 끌 수 있다. | Must |
| A-4 | 스레드: 최근 대화 이어가기, 새 대화, 스레드 목록, 오래된 메시지는 요약으로 압축. | Must |
| A-5 | 확인·되돌리기: destructive 도구는 확인 카드 후 실행. write 도구는 즉시 실행 + 30초 되돌리기. | Must |
| A-6 | 컨텍스트 조립: 현재 시각·타임존, 오늘 일정(≤10), 마감·지연 할 일(≤10), 관련 기억 top-k(≤8), 스레드 요약. 동적 컨텍스트 토큰 예산 ≤ 6K. | Must |
| A-7 | 음성 입력: 길게 누르기 → 짧은 WAV 클립을 Muse 배치(PUSH_TO_TALK 모드)로 전사. 5초 클립 ≈ $0.00025. | Should |
| A-8 | 제안 칩·슬래시 명령: "오늘 브리핑", "이 회의 요약", "내일 일정 정리". | Should |
| A-9 | 능동 제안은 브리핑에서만. 채팅 중 먼저 말 걸지 않는다. | Should |
| A-10 | 매 응답 아래에 토큰·비용 칩 표시(기본 켬, 설정에서 숨김). 도구 실행 비용도 합산. | Must |

**페르소나** — 한국어, 친근한 존댓말(해요체, 설정에서 변경 가능), 간결, 결과 먼저. 모르면 모른다고 말하고 데이터를 지어내지 않는다. 기억·회의를 인용할 때는 근거 링크를 단다.

**수용 기준**
- FAB 탭 → 입력 가능까지 300ms.
- 첫 토큰 1.5초 이내(luna, reasoning effort low).
- 대화 1턴 평균 비용 < $0.002.
- "내일 오후 비는 시간에 리뷰 잡아줘" → `findFreeSlots` → `createEvent` 2스텝 성공.
- 파괴적 요청("이 보드 카드 다 지워")은 반드시 확인 카드를 거친다.

### 5.5 Memory

**목적** — 레이첼의 장기 기억을 만들고, 사용자가 볼 수 있게 한다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| ME-1 | 기억 유형: `fact` · `preference` · `person` · `decision` · `goal` · `routine`. 각 기억은 내용·중요도·출처(회의/대화/캡처 링크)·시각을 가진다. | Must |
| ME-2 | 자동 추출: 대화 스레드 유휴 10분 후, 회의 요약 직후 잡으로 추출(luna 구조화 출력). 임베딩 유사도 ≥ 0.92면 병합, 아니면 생성. | Must |
| ME-3 | 검색 인덱스: 카드·일정·회의 전사·기억을 chunk로 나눠 임베딩(pgvector) + 키워드(pg_trgm) 하이브리드 검색. | Must |
| ME-4 | 기억 화면: 유형별 목록, 검색, 편집·삭제·고정(pin), "왜 기억하나요?" 출처 보기. | Must |
| ME-5 | 수동 기억: "이거 기억해" 도구, 화면에서 직접 추가. | Must |
| ME-6 | 사용 추적: 답변에 쓰인 기억은 `last_used_at`·`use_count` 갱신 → 랭킹 반영. 1년 미사용은 아카이브 제안. | Should |
| ME-7 | 전역 검색(⌘K): 모든 모듈을 한 번에. | Should |

**레이첼 도구** — `memory.remember`, `memory.recall(query)`, `memory.update`, `memory.forget`(destructive), `search.all(query, types)`

**수용 기준**
- 회의 요약 후 5분 내 관련 기억 생성.
- 같은 사실이 두 번 저장되지 않는다(유사도 병합).
- 기억을 삭제하면 다음 답변부터 즉시 반영된다.

## 6. 제안: 원안보다 나은 방법

요청하신 항목을 그대로 살리되, 아래는 더 싸거나 더 단순하거나 더 확장성 있는 대안이다. 각 항목의 채택 여부는 11장에서 확정한다.

| # | 원안 | 제안 | 이유·효과 | 트레이드오프 |
|---|---|---|---|---|

## 7. 비기능 요구사항

### 7.1 성능 예산

| 지표 | 목표 | 측정 조건 |
|---|---|---|
| LCP | ≤ 1.8s | 모바일 4G, 중급기, Today·Tasks |
| INP | ≤ 200ms | 카드 드래그, 채팅 입력 |
| 첫 JS | ≤ 180KB gzip | Today 라우트. 차트·DnD·마크다운은 지연 로드 |
| 재방문 첫 페인트 | ≤ 500ms | TanStack Query 캐시(IndexedDB) 히트 |
| 채팅 첫 토큰 | ≤ 1.5s | luna, effort low, 컨텍스트 ≤ 6K |
| 전사 지연 | ≤ 30s(라이브 패스) | 60분 회의, Wi-Fi |

기법: Server Components로 목록 렌더, 낙관적 업데이트, 라우트 prefetch, 이미지 최적화, 폰트는 시스템 스택 우선(Pretendard는 옵션), Realtime 구독은 보이는 테이블만.

### 7.2 PWA

- Serwist 기반 서비스 워커. 앱 셸 프리캐시, 페이지 NetworkFirst, 정적 자원 StaleWhileRevalidate, `/api/chat`은 NetworkOnly.
- 오프라인: 캐시된 목록 조회 가능, 쓰기는 안내(P6에서 아웃박스).
- 매니페스트: standalone, 아이콘 세트, 바로가기 3개, Share Target(P4).
- 웹 푸시(P5). Wake Lock(회의 중).

### 7.3 보안·프라이버시

- 모든 테이블 RLS: `(select auth.uid()) = user_id`, `TO authenticated`, UPDATE는 `USING` + `WITH CHECK`. 뷰는 `security_invoker = true`.
- 비밀은 서버 전용. `NEXT_PUBLIC_`에는 Supabase publishable key만.
- Google refresh token은 Supabase Vault에 저장, `integrations`는 secret id만 참조.
- Meta·OpenAI API 키는 서버 전용. 브라우저는 우리 라우트에만 오디오를 보낸다(Meta Realtime은 키가 핸드셰이크에 들어가므로 직결 금지).
- 크론 엔드포인트는 비밀 헤더 검증. 채팅 라우트는 사용자별 시간당 호출 상한.
- 오디오는 v1에서 서버에 저장하지 않는다(기기 IndexedDB). Storage 업로드 옵션(v1.5)을 켜면 private 버킷 + user_id 경로 RLS.
- 전체 내보내기(JSON) · 계정 삭제 시 전량 삭제.

### 7.4 접근성·i18n

- 키보드로 칸반 이동·채팅·팔레트 조작 가능. 포커스 링 유지. 색 대비 AA.
- UI 문자열은 사전(`ko`, `en`)으로 분리. 날짜·시간은 사용자 타임존(`Asia/Seoul` 기본).
- `prefers-reduced-motion` 존중.

### 7.5 관측

- `llm_usage`(비용), `jobs`(실패·재시도), `domain_events`(활동 로그). Vercel 로그로 충분. Sentry는 옵션.

2. 월 예산은 선택 사항. 설정하면 80%·100%에서 배너 경고. 설정하지 않으면 대시보드에 누적과 추이만 보여 준다(실사용 후 결정).
3. 시스템 프롬프트와 도구 정의는 고정 접두어로 두어 프롬프트 캐시 적중률을 높인다.
4. reasoning effort 기본값: chat/extract `low`, summarize `medium`, weekly review `medium`. `high` 이상은 쓰지 않는다.
5. 브리핑·주간 리뷰·요약은 결과를 저장하고 재생성은 명시적 요청에만.

| 용어 | 뜻 |
|---|---|
| 모듈(Module) | `RachelModule` 계약을 구현한 기능 단위. nav·도구·위젯·잡·인덱서를 선언한다. |
| 도구(Tool) | 레이첼이 호출하는 함수. zod 입력 스키마·위험 등급·실행·(선택) 되돌리기를 가진다. |
| 도메인 이벤트 | `task.created`처럼 모듈이 발행하는 사실. 다른 모듈은 구독만 한다. |
| 잡(Job) | `jobs` 테이블의 비동기 작업 단위. pg_cron이 1분마다 처리 라우트를 호출한다. |
| 세그먼트 | 회의 오디오를 무음 경계로 자른 8~20초 PCM 조각. 라이브 패스 전사·저장의 단위. |
| 패스(Pass) | 라이브 패스(회의 중 근실시간, 화자 없음)와 파이널 패스(종료 후 화자 분리 재전사). |

| 스티칭 | 청크 간 겹침 구간의 turn을 대조해 화자 라벨(A/B…)을 전역 라벨(화자 1·2…)로 잇는 절차. |
| 기억(Memory) | 레이첼이 추출·저장한 사실·선호·결정. 임베딩과 출처를 가진다. |
