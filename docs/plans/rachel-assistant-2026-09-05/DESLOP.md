# 변경 파일 단순화 검토

범위: 이번 P0–P3 변경 파일. 기존 전체 파일의 스타일 통일이나 무관한 리팩터링은 수행하지 않았다. 적용 스킬: ai-slop-cleaner 표준 모드.

## 행동 고정 및 정리 계획

승인·Undo·서비스 버전·오늘 계획·대화 재개 회귀를 먼저 실행했다. 이후 (1) 내부 구현 데이터의 사용자 화면 노출, (2) 중복된 설정 병합, (3) 실패를 정상 결과로 바꾸는 처리, (4) 사용하지 않게 된 코드 순서로 확인했다.

| 발견 | 분류 | 처리 |
|---|---|---|
| 도구 결과 펼치기에 전체 JSON 표시 | 사용자에게 불필요한 내부 데이터 | 업무 결과·대상 링크·불완전 범위·Google 상태만 표시. 내부 키/원문 전체 덤프 제거 |
| 알림 pre-read 중첩 전체 객체 재작성 | 중복 처리와 경계 오류 | 공통 profile CAS 내부에서 제출 필드만 병합 |
| 통계 오류를 빈 배열/0으로 합성 | 실패를 숨기는 fallback | 조회 오류 전파, 리뷰 모델 호출·저장 중단. 모든 읽기 오류 회귀 |
| 컨텍스트 제공자 오류 | 검증된 fail-safe | 다른 자료는 유지하되 해당 자료 조회 실패를 프롬프트에 명시. 없음으로 단정하지 않게 함 |
| 임베딩 장애 시 키워드 검색 | 검증된 fail-safe | 저장·고정 기억 유지, 검색 제한을 표시. 의미 검색 성공으로 오인하지 않게 함 |
| 결과 불명 쓰기 재개 | 검증된 복구 경계 | 조회와 생성 추적 근거가 있는 요청만 재개. 범용 쓰기 자동 재실행 없음 |
| 마지막 단계 보고 도입 뒤 finishReason 변수 | 새로 생긴 불필요 코드 | 변수 제거, 실제 단계 수로 제한 표시 |
| 대화 교체 시 이전 로딩 결과·캐시 재사용 | 오래된 상태를 정상 값으로 쓰는 경로 | 로딩 결과에 threadId 결속, 삭제된 캐시/초안 제거 |

## 화면 검토

375px Today와 모바일 승인 화면의 실제 캡처를 확인했다. 마감과 계획을 구분하고, 확인 불가능한 가용 시간은 그 상태를 표시한다. 주요 본문은 기존 text-sm/14px 기준을 유지하고 실행 기록·결과 설명도 작은 내부 로그 형태를 줄였다. 기존 흑백 브랜드·단일 제안과 접힌 나머지 목록을 유지했다. 새 그림자·그라디언트·장식 카드 시스템을 추가하지 않았다.

캡처는 Next 개발 서버의 지표 아이콘을 포함하므로 운영 화면의 시각 증거로 오인하지 않는다. body 전체 스크린샷에서 고정 하단 요소가 중간에 보이는 현상과 실제 375px overflow 검사는 구분했다.

## 검증 및 남은 사항

정리 후 승인/컨텍스트/도구 어댑터 15개 검사 통과, 이후 전체 테스트·타입·빌드와 브라우저를 재실행했다. 최종 명령 결과는 REVIEW.md가 기준이다. 추가 의존성·대규모 추상화 도입 없음. 기존 무관한 Biome 경고는 일괄 삭제하지 않았다. 외부 요청 취소·동시 원격 쓰기·실기기 미검증 한계는 REVIEW.md에 남겼다.
