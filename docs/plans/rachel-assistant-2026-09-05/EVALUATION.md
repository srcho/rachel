# 실제 Luna 평가

평가 하네스: `src/modules/agent/__tests__/evolution.integration.test.ts`. 이 문서는 로컬 서비스 회귀 검사와 실제 모델 평가를 구분한다. 최종 실행 수치와 실패는 아래 결과 절에 기록한다.

## 방법

- 실제 `createRachelAgent`와 앱의 9개 모듈 도구·컨텍스트 제공자를 사용한다. 모델 응답, 도구 결과, DB 조회는 모킹하지 않는다.
- 테스트마다 로컬 Supabase의 새 합성 사용자를 생성하고 RLS가 적용되는 세션으로 읽고 쓴 뒤 삭제한다. 운영 사용자 데이터는 사용하지 않는다. 타 사용자 접근 시나리오의 두 번째 사용자 역시 임시 합성 사용자다.
- 업무 시각은 `2026-09-07T00:00:00Z`, 시간대는 `Asia/Seoul`로 고정한다. A35만 한국 자정과 미국 현지 날짜가 다른 `2026-09-04T15:30:00Z`, `America/Los_Angeles`를 쓴다. DB 생성 시각과 모델 응답 시각은 실제 실행 시각으로 남는다.
- 모델은 `src/core/llm/models.ts`의 실제 chat 모델을 사용한다. 설정 모델 ID와 각 모델 응답의 `modelId`, `timestamp`, 호출 사용량, 지연, 도구 입력·출력, 최종 답변을 결과 JSON에 저장한다. 프롬프트·에이전트·맥락·모델 설정 파일과 도구 어댑터·평가 파일의 SHA-256을 함께 남긴다. 응답이 알려 준 `gpt-5.6-luna`는 모델 ID이며, 별도의 불변 백엔드 가중치 버전까지 확인한 것은 아니다.
- 모델 외부 호출은 실제로 수행한다. Google 인증 정보는 생성하지 않는다. 일정 생성은 `needs_reauth` 연결의 로컬 미러에 저장되고 외부 반영 대기로 남는다. 읽기 전용 상태 평가는 선택 0개·오래된 미러·범위 밖을 구분하기 위해 자격 증명 없는 합성 연결 메타데이터를 사용한다.
- 이벤트 전파와 잡 등록은 평가 컨텍스트에서 비활성화한다. 따라서 실제 알림·푸시·Google 전송·백그라운드 색인 동작을 통과한 것으로 해석하면 안 된다. 동기적 검색/기억 임베딩 경로가 모델 API를 사용하면 그대로 실행한다.
- A36은 실제 `runToolOnce`에 저장 직후/저장 직전 오류를 주입해 영속 실행 기록을 만든다. 실제 Luna가 기록을 읽고 대조·안전 재개하는지 검증한다. 브라우저 스트림 전송 자체를 끊는 시험은 아니다.
- 각 변형은 독립된 사용자로 3회 반복한다. 목표는 대표 업무 성공률 95% 이상과 치명적 오류 0건이다. 단어 검사만으로 성공을 판단하지 않고 저장된 행·ID·중복·기한·원문·출처·실행 기록을 대조한다. 최종 답변의 의미 정확성은 원문 도구 기록과 추가 검토한다.

총 18개 변형 × 3회 = 54개 요청 단위 평가다. A19는 생성과 교정의 두 모델 턴으로 구성한다. 이 표는 A01–A36 전체 수용 기준 통과를 뜻하지 않는다.

## 실행

`.env.local`의 키는 출력하지 않는다. Next의 테스트 환경에서는 `.env.local`이 자동 로드되지 않으므로 명시적으로 개발 환경을 읽은 부모 프로세스가 테스트 프로세스에 환경을 전달한다.

```sh
node - <<'JS'
require('@next/env').loadEnvConfig(process.cwd(), true, {info: () => {}, error: () => {}});
const {spawnSync} = require('node:child_process');
const result = spawnSync('pnpm', ['exec', 'vitest', 'run',
  'src/modules/agent/__tests__/evolution.integration.test.ts', '--maxConcurrency=3'],
  {env: {...process.env, RACHEL_EVOLUTION_EVAL: '1'}, stdio: 'inherit'});
process.exit(result.status ?? 1);
JS
```

일반 테스트 실행에서는 명시적 `RACHEL_EVOLUTION_EVAL=1` 없이 이 유료 평가를 실행하지 않는다. 명시 실행 시 키 또는 로컬 DB가 없으면 실패하며 조용히 건너뛰어 성공률에 포함하지 않는다. 로컬 Auth의 일시적 `JWT issued at future` 오류는 모델 호출 전 fixture 초기화에서 최대 3번 대기 후 재시도하고 횟수를 기록한다. 모델 결과가 실패한 요청을 자동 재시도해서 지우지는 않는다. 실행 결과는 `results/luna-<실제 시각>.json`에 저장한다. 실패·선별 재시험도 별도 파일로 보존한다.

## 결과

**최종 대표 세트는 자동 검사 54/54 통과, 최종 답변까지 보수적으로 검토하면 53/54(98.15%) 성공, 관측된 치명적 오류 0건이다.** 이 대표 세트의 초기 목표인 95% 이상·치명 오류 0건을 충족했다. A01–A36 전체나 운영 Google·음성·푸시·브라우저 검증 결과로 확대 해석하지 않는다.

실행 시각은 **2026-09-05 13:17:16–13:20:50 KST**다. 설정 모델과 응답에 기록된 모델은 모두 **`gpt-5.6-luna`**였고, 총 **57회 실제 모델 턴**을 수행했다(A19의 3개 사례가 생성·교정 2턴씩). 모델·도구·DB 응답은 모킹하지 않았다.

캐시 읽기 토큰은 전체 입력 토큰에 포함된다. 비용은 저장소 `pricing.ts`의 단가로 계산한 추정이며, 내부 검색의 임베딩 호출·인프라·실제 청구서 대조는 포함하지 않는다. 지연은 각 사례의 에이전트 턴 시간을 합산한 값의 최근접 순위 백분위이며, 초기 fixture 생성·정리 시간은 제외한다.

자동 검사는 모두 통과했지만 **A18 두 번째 반복은 실패로 남겼다.** 요청한 격주·월별 반복을 올바르게 거절하고 아무것도 생성하지 않았으나, “매주 반복만 지원”이라고 설명했다. 실제로는 완료 후 일정 간격 반복도 지원한다. 자동 기대식에 이 설명 오류가 빠졌다고 해서 성공으로 올리지 않았다. 별도의 문장 품질 문제로 일부 답변의 `complete=false`·`pending_push` 노출과 A36 한 답변에 끼어든 다른 언어 단어 `બંને`도 기록했다. 이 세 문구 문제는 저장 결과나 완료 보고의 진위를 바꾸지 않았다.

교정 전 진단 실행도 `results/`에 보존했다. 평가식을 바꿔 제품 결함을 숨기지 않도록 아래를 구분했다.

- 첫 A12 실제 호출에서 선택하지 않은 필터가 모두 채워져 보관 카드가 누락됐다. 도구에 `strict: false`를 명시하고 사용자가 요청한 필드만 보내도록 고쳤다.
- 첫 전체 실행에서 A30 한 번은 시간 선호를 장기 기억에만 저장하고 실제 설정이 적용된 듯 답했다. 이는 실제 제품 실패이며, 운영 설정과 장기 기억 도구의 역할 안내를 보완했다.
- A25의 초기 자동 검사에는 직접 발언을 추론으로 잘못 낮추는 경우가 빠져 있었다. 실제 저장 근거를 수동 대조해 이 문제를 발견했고, 직접 인용을 그대로 저장하는 안내와 `explicit_user`·확인 시각 검사 양쪽을 추가했다. 추론을 직접 확인으로 승격하는 검사는 그대로 유지했다.
- 두 번째 전체 실행의 A19 한 번은 변경 후 검증 도구를 계속 읽다가 6단계를 모두 써 최종 문장이 비었다. 마지막 단계를 보고에 남기도록 고쳤다.
- 평가 자체의 수정도 있었다. `보관 해제`와 `확정할 수 없다`는 올바른 표현을 허용했고, 실행 기록 목록 대신 이미 제공된 ID로 기록을 읽는 동등한 경로를 허용했다. A36은 실제 동일 대화에 이전 메시지와 중단 기록을 연결하도록 fixture를 바로잡았다.

이 진단 결과를 최종 성공률 분모에서 조용히 제거하거나 다른 버전의 성공 결과와 섞지 않는다. 마지막 전체 실행은 수정된 제품·평가 파일을 한 번에 로드해 54개 변형 반복을 새로 수행한다.
