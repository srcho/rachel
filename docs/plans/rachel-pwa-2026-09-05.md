## 대화 복구 규칙

- 창을 닫거나 대화 목록을 열어도 진행 중인 SDK 요청을 재생성하지 않는다.
- 복귀 시 살아 있는 스트림에는 큐에 쌓인 응답을 전달할 시간을 준다. 진행이 없는 연결은 서버의 120초 실행 한도에 맞춘 유휴 시간 후 종료하고 저장된 결과를 조회한다. 긴 도구 실행을 30초 만에 중단하지 않는다.
- 저장이 조금 늦어지는 경우 미완료 메시지를 최대 5회, 3초 간격으로 다시 조회한다. 조회 자체는 10초 제한을 둔다.
- 복구 중 새 메시지나 승인 상태가 바뀌면 앞서 시작한 조회 결과로 덮어쓰지 않는다.
- 복귀는 조회만 수행한다. 원래 요청이나 변경 작업을 자동 재전송하지 않는다.
- 오프라인에서는 초안 편집을 유지하고 전송을 막는다. 네트워크 실패가 입력 내용이나 기존 메시지를 지우지 않는다.
- sessionStorage는 같은 브라우저 세션의 새로고침 복원용이다. 완전히 종료된 앱의 세션 보존 여부는 OS와 브라우저에 달려 있다.

## 검증 결과

로컬 Supabase의 격리된 테스트 사용자와 35개 카드 / 4개 컬럼을 사용했다. 운영 데이터는 변경하지 않았다.

| --- | --- |
| 전체 Vitest | 299 통과, 60 건너뜀. 71개 파일 통과, 4개 파일 건너뜀 |
| 복구 회귀 테스트 | 새 테스트 9개: 인스턴스 유지, 사용자 격리, 초안 복원, 메시지 병합, 복귀 조회, 조회 경합, 늦은 저장, 연결 오류, 키보드 영역 |
| 기존 브라우저 수용 시나리오 | 모바일·데스크톱 12/12 통과. 새로고침 후 자동으로 복원되는 대화에 맞춰 기존 검증 갱신 |

| 화면 크기 | 320×568, 375×812, 812×375, 1280×720, 1440×900에서 문서 크기 = 뷰포트 크기. 목록·보드 내부 스크롤 유지 |
| 키보드 영역 모사 | 375×812 화면에서 가시 높이 430px: 패널 하단 430px, 입력창 하단 423px. 닫힘 후 원래 높이·너비 복원 |
| 응답 도중 닫기 / 재개방 | 지연된 UI 스트림으로 답변 수신 확인. `/api/chat` 요청 1회 |
| 앱 밖에서 저장된 메시지 | 숨김 상태에서 격리된 서버 응답 변경 후 foreground 이벤트로 자동 반영 |
| 대화 목록 복귀 | 목록을 연 채 숨김 상태에서 서버 제목 변경 후 foreground 이벤트로 자동 반영 |
| 실제 서비스 워커 | `next start`에서 `/sw.js`가 페이지를 제어하는 것 확인. 재연결 후 동일 문서 유지, 초안 유지, 전송 버튼 복구 |
| 오프라인 안내 → 복귀 | 미캐시 `/settings?...` 접근 시 안내 화면 표시. 온라인 복귀 후 원래 URL의 설정 화면 자동 표시 |

브라우저의 승인·취소·삭제 테스트는 실제 UI·서버·DB와 모델 제공자 스텁을 사용했다. 지연 스트림 테스트는 브라우저에서 응답 스트림을 주입했다. 이번 결과는 모델 품질 평가가 아니다.

실물 iPhone / Android에 설치한 PWA의 소프트 키보드, OS에 의한 프로세스 강제 종료는 직접 검증하지 않았다. 키보드 검증은 Chromium의 뷰포트 변경·VisualViewport 이벤트 모사다. 운영 배포 검증은 포함하지 않는다.
