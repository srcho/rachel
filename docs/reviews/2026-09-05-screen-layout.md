# 화면 높이·스크롤 검수

2026-09-05 · 로컬 Chromium · 로컬 검수 계정

## 수정 결과

| 발견한 문제 | 원인 | 수정·확인 |
| --- | --- | --- |
| 데스크톱 캘린더에 불필요한 페이지 스크롤 | 본문에서 머리글 높이를 고정값으로 뺐지만 실제 테두리·동기화 안내 높이가 추가됨 | 머리글과 안내를 포함한 flex 레이아웃에서 남은 높이 사용. 연결 전 1px, 연결 후 22px 넘침 → 0px |
| 녹음 화면에 1px 페이지 스크롤 | 같은 머리글 높이 계산 | 화면 전체를 뷰포트에 맞추고 녹음 본문이 남은 높이 사용 → 0px |
| 주간 캘린더의 작은 데스크톱 창에서 가로 스크롤 | 760px 최소 너비 | 44rem으로 조정. 820×620에서 시간표 가로 넘침 10px → 0px |
| 주간 시간 눈금·일정 위치 불일치와 끝부분 빈 공간 | 눈금은 3.5rem, 일정 좌표는 시간당 56px | 눈금도 56px로 통일. 루트 글꼴 14px·20px에서 10:30 일정이 10시 눈금 아래 28px에 위치 |
| 리뷰의 빈 차트가 과도한 공간 사용 | 데이터가 없어도 차트를 렌더링하고 위젯 행 높이를 고정 | 내용에 맞는 행 높이와 짧은 빈 상태. 1440px 너비에서 빈 지표 카드 약 397px → 85px |

공통 `Page`는 너비만 결정하고, 높이를 제한해야 하는 캘린더·녹음 화면이 직접 높이를 관리한다. 캘린더 하단에는 빠른 메모·레이첼 버튼이 마지막 행을 가리지 않도록 공간을 확보했다.

## 브라우저 검수 범위

화면 크기: **1440×900, 820×620, 390×844, 320×568**.

14개 경로 × 네 크기 = **56개 조합**: 오늘, 할 일, 캘린더 월간·주간·일정 목록, 회의 목록, 메모리, 인박스, 리뷰, 설정, 더보기, 회의 상세, 인박스 상세, 녹음.

- 56개 조합 모두 HTTP 200, 문서 가로 넘침 0px.
- 데스크톱 캘린더 세 뷰, 모든 크기의 주간 캘린더·녹음 화면에서 문서 세로 넘침 0px.
- 연결 해제 안내가 있는 캘린더도 820×620의 세 뷰와 320×568의 주간 뷰에서 문서 넘침 0px.
- 빠른 메모·회의 메모·일정·할 일 입력창을 1440×700과 320×568에서 확인: 8개 모두 화면 안에 표시되고 가로 넘침 없음.
- 레이첼 대화 패널은 열린 애니메이션이 끝난 상태에서 390×844와 320×568의 너비·하단 경계에 정확히 맞음.
- 리뷰는 데이터가 있을 때 차트 6종이 모두 표시됨. 완료 소요 시간 0시간, 캡처 정리율 0%도 유효한 데이터로 표시됨. 데이터가 없으면 6종 모두 간결한 안내만 표시됨.

[전체 측정값](./2026-09-05-screen-layout.json)의 `x`, `y`는 문서가 뷰포트보다 큰 픽셀 수다. `inner`, `horizontal`은 스크롤 가능한 내부 영역이다. 측정 당시 인박스 항목 1개가 있어 리뷰의 캡처 차트가 표시되며, 완전히 빈 리뷰는 별도 확인했다.

## 유지한 스크롤

- 설정의 긴 입력 폼, 오늘의 여러 위젯, 긴 일정 목록 등 실제 내용이 화면보다 길면 페이지 스크롤을 사용한다.
- 작은 모바일에서 월간 뷰의 날짜 칸은 읽고 누를 수 있는 높이를 유지한다. 320×568에서는 6주 달력과 머리글·하단 공간 때문에 106px의 세로 스크롤이 남는다.
- 모바일 주간 뷰는 7일을 읽을 수 있도록 시간표 내부의 가로 이동을 유지한다. 세로 이동도 시간표 내부에서 이루어진다.
- 리뷰는 데이터가 쌓이거나 모바일에서 카드가 한 열로 배치되면 내용에 따라 스크롤된다.

## 검증

- `pnpm typecheck` 통과.
- 캘린더 날짜·시간 계산, 회의, 리뷰 관련 Vitest: 18개 파일 / 72개 테스트 통과.
- 변경한 10개 파일 Biome 검사 통과.
- `pnpm build` 통과, 서비스 워커 생성 완료.
- 실제 iOS PWA·소프트 키보드·백그라운드 복귀 동작은 이번 Chromium 화면 크기 검수에 포함하지 않았다. 녹음 화면은 마이크 권한이 없는 상태의 레이아웃을 확인했다.
