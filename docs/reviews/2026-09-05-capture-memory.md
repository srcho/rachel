# 설치 아이콘 · 빠른 메모 · 기억 검토

## 적용한 변경

### 설치 아이콘

- ImageGen으로 종이와 책갈피를 연상시키는 소문자 r 심벌을 제작했다. 아이보리 바탕, 차콜 심벌, 코럴 접힌 모서리다.
- iOS 180px, Android/PWA 192px·512px, maskable 512px와 16/32/48px favicon을 교체했다.
- 둥근 외곽과 투명 여백을 이미지에 미리 넣지 않았다. 운영체제 마스크가 외곽을 결정한다.
- 원본: `design/rachel-icon.png`. 재생성: `node scripts/gen-icons.mjs`.
- manifest와 Apple 아이콘 주소에 버전을 붙였다. 앱 바로가기에는 ‘빠른 메모 · 링크 저장’을 표시한다.

### 빠른 메모와 수집함

- 일반 화면의 우하단 ‘메모’ 버튼으로 현재 화면을 떠나지 않고 메모를 작성한다. 대화 중·회의 녹음 중에는 겹치는 버튼을 숨기고 수집함에서는 본문 입력창을 사용한다.
- 초안은 사용자별로 이 기기에 보관된다. 입력창을 닫거나 페이지를 다시 열어도 이어 쓸 수 있다.
- 수집함 자체에도 입력창, 붙여넣기, 저장 버튼, 저장된 항목의 바로가기를 제공한다.
- 메모에 포함된 HTTP(S) 링크는 별도 URL로 함께 저장한다. 원문은 유지한다. 4,000자가 넘으면 내용을 자르지 않고 나눠 저장하도록 안내한다.
- 네트워크가 끊기면 기존 IndexedDB 아웃박스에 넣고 ‘기기에 보관됨’을 표시한다. 연결되면 같은 생성 ID로 재전송한다.
- 오프라인 저장 직후 서버 페이지를 다시 요청하지 않는다. 새로고침으로 화면이 끊기는 문제를 피한다.
- 공유 URL 진입은 미리보기만 한다. 사용자가 저장을 눌렀을 때 기록하며 실패 시 원문을 유지한다. 공유 URL을 새로고침하는 것만으로 기록을 만들지 않는다.
- Android의 설치된 PWA는 공유 대상으로 사용할 수 있다. iPhone은 링크 복사 → 레이첼 메모 → 붙여넣기 경로를 안내한다. [MDN share_target](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/share_target), [MDN 호환성 데이터](https://github.com/mdn/browser-compat-data/blob/main/manifests/webapp/share_target.json).
- AI 분류와 원문 저장은 구분한다. 미분류 메모를 ‘분류하는 중’으로 단정하지 않고 저장 완료·분류 대기로 표시한다. 기존 직접 정리/확정 동선은 계속 제공한다.
- 운영에서 확인한 Structured Outputs 응답 스키마 오류를 수정했다. 모델 출력은 모든 키를 필수로 정의하고 비해당 제안은 null을 사용하며, 기존 도메인 구조로 변환한다.

## 기억의 실제 트리거

| 진입점 | 현재 동작 |
| --- | --- |
| 기억 화면에서 직접 입력 | 명시적으로 저장한다. 기존 기억과 충돌하면 검토 대상으로 남긴다. |
| 대화에서 ‘기억해 줘’ 요청 | 레이첼이 memory.remember 도구를 사용한다. 실제 사용자 발언 근거가 검증된 경우 직접 확인한 기억으로 취급한다. |
| 레이첼 응답 완료 | 같은 대화의 추출 작업을 약 10분 뒤로 예약한다. 이미 대기 중이면 합쳐진다. 마지막 발언 기준으로 계속 10분씩 미루는 방식은 아니다. |
| 대화 자동 추출 | 실행 시 최근 30개 메시지 중 사용자 텍스트를 읽는다. 추출 프롬프트에는 최대 20,000자를 전달한다. |
| 회의 요약 완료 | 요약과 내용 버전을 담은 추출 작업을 예약한다. 현재 내용 버전과 맞지 않으면 오래된 작업을 건너뛴다. |
| 수집함 저장 | 원문과 분류 제안을 저장한다. 사용자가 기억으로 확정할 때 장기 기억을 만든다. |

대화·회의 자동 추출의 대상은 오래 쓸 사실, 선호, 사람, 결정, 목표, 습관이다. 근거 문구가 입력에 실제 존재해야 저장한다. 일회성 일정·할 일과 잡담은 대상에서 제외하도록 지시한다. 자동 추출 후보는 직접 확인한 기억과 구분하며, 충돌 검토 중인 항목은 답변에 제공하지 않는다.

### 발견하고 고친 기억 문제

1. **짧은 선호 누락**: 기존 코드는 20자 미만이면 의미를 보지 않고 종료했다. ‘고수는 안 먹어요’도 탈락하는 테스트를 먼저 실패시킨 뒤, 공백 입력만 건너뛰도록 수정했다. 실제 근거 검증은 유지한다.
2. **재요약 후 추출 누락**: 같은 회의의 새 요약이 대기 중인 옛 요약 작업에 합쳐지면, 옛 작업은 버전 검사에서 건너뛰고 새 요약은 추출되지 않았다. 중복 방지 키에 요약 버전을 포함했다.
3. **작동 여부가 보이지 않음**: 기억 화면에 저장 규칙과 최근 추출 상태, 갱신 시각, 수동 새로고침을 추가했다. 화면이 보일 때 30초 간격 및 앱 복귀 시 갱신한다.
4. **출처 대화로 돌아가기 어려움**: 기억의 대화 출처에서 해당 대화를 바로 열 수 있게 했다.

## 운영에서 읽기 전용으로 확인한 사실

2026-09-05 KST 점검 시:

- 장기 기억은 0개였다.
- 최근 조회한 memory.extract 8건은 모두 done이었다. 작업 완료는 새 기억 생성과 동의어가 아니다.
- 수집함에는 inbox 상태 1건이 있었고, capture.triage 작업에서 응답 JSON Schema의 required 필드 오류가 확인됐다.
- 운영 memories 테이블에는 로컬 코드가 사용하는 index_status 컬럼이 없었다.
- migration list 결과 기존 작업의 마이그레이션 16개(20260905034618–20260905041942)가 운영에 미적용이었다.

과거 추출 결과의 후보 수·탈락 사유는 jobs 행에 기록되지 않아 ‘왜 0개였는지’를 사후에 확정할 수 없다. 위 오류와 누락 조건은 확인된 사실이며, 모든 과거 대화가 그 조건에 해당했다는 뜻은 아니다. 점검 중 운영 메모나 작업을 생성·수정하거나 운영 큐를 수동 실행하지 않았다.

## 다음 개선 제안

1. **추출 결과를 남기기**: 각 작업에 확인한 발언 수, 후보 수, 생성/병합 수, 건너뛴 이유를 남긴다. ‘실행 완료, 새 기억 없음’과 추출 실패를 분리할 수 있어야 한다.
2. **후보 확인을 한 번의 선택으로**: ‘맞아요 / 수정 / 기억하지 않기’로 검토하고 원본 근거를 함께 보여준다. 중요한 기억은 고정하도록 안내한다. 수정으로 원본 출처를 덮어쓰는 대신 확인 이력을 별도로 남기는 설계가 필요하다.
3. **자동 기억 범위 선택**: 대화/회의별 자동 기억 켜기·끄기와 특정 대화 제외를 제공한다. 기능을 이해한 후 조절할 수 있게 기본 화면에는 상태만 간결하게 표시한다.
4. **사용 사실 설명**: 현재는 답변에 제공한 기억 후보와 실제 답변에 반영한 기억을 구분해야 한다. ‘이번 답변에서 참고한 기억’의 근거와 정정 동선을 제공하는 방향이 좋다.

## 검증

- Vitest 전체: 310개 통과, 기존 60개 스킵. 짧은 선호 재현/수정 테스트를 포함한 메모리·수집함 집중 검증 20개도 통과.
- 기존 assistant Playwright: 모바일/데스크톱 12개 통과.
- 수동 CLI 브라우저: 390px 수집함·기억 화면 가로 넘침 없음, 저장 후 목록 반영, 공유 미리보기·저장, 초안 닫기/복원, 오프라인 보관/온라인 자동 전송 확인.
- 키보드 표시 영역을 360px로 모사했을 때 메모 창이 390×360으로 조정되고 복귀 후 390×448로 회복됨. 데스크톱은 392px 대화상자로 표시.
- 실제 Luna API: 링크 메모와 할 일 분류 모두 finishReason=stop. 가상 선호·습관 발언에서 기억 후보 2개 추출. 사용자 개인정보를 모델 검증 입력으로 사용하지 않음.
- TypeScript 검사·Next/Serwist 빌드 성공. Lint 오류 없음(기존 경고 26개).
- 스크린샷: `output/playwright/capture-inbox-mobile.png`, `capture-quick-mobile.png`, `capture-quick-desktop.png`.
- 실제 iPhone 홈 화면 설치 및 OS 키보드 동작은 데스크톱 브라우저 모사만으로 검증되지 않는다.

## 반영 범위

코드와 아이콘은 로컬에 적용했다. 이번 변경에 새 DB 마이그레이션은 없다. 운영 배포는 수행하지 않았다. 운영에 적용할 때는 위 16개 기존 마이그레이션을 포함한 통합 릴리스를 검토하고, DB 반영 및 실제 조회/RPC 검증을 앱 배포보다 먼저 진행해야 한다. 현재 상태에서 프런트만 배포하면 기억 조회 등 기존 코드와 운영 DB가 맞지 않는다.
