# 투데이 제안·메모 기억 저장 장애 복구

## 확인한 원인

운영 로그와 실제 운영 DB를 대조했다.

- `/today`: `PGRST205`, `public.notification_controls` 테이블 누락으로 제안 위젯 조회가 실패했다.
- `/capture` 확정 요청: `PGRST204`, `memories.index_status` 컬럼 누락으로 기억 생성이 실패했다. 브라우저에는 서버 상세 오류를 숨기는 React 441 메시지가 표시됐다.
- 기존 `capture.triage` 작업 1건은 AI 응답 스키마의 필수 키 누락으로 두 번 실패한 기록이 있었다. 해당 스키마 수정은 앞선 코드에 들어 있었지만 실패한 작업은 자동으로 재개되지 않았다.
- 운영 DB는 25개 마이그레이션까지만 반영돼 있었고, 앱이 사용하는 후속 16개 변경은 미적용이었다. 앞선 로컬 검증만으로 운영 호환성을 보장하지 못했다.
- 문제의 메모 원문은 저장돼 있었다. 사용자가 선택한 기억 분류가 `resolving`에 남아 있고, 연결된 기억은 없었다.

## 운영 복구

1. 미적용 SQL 16개를 검토하고 dry-run으로 대상을 확인했다. pending 작업의 중복 키가 없음을 조회했다.
2. `supabase db push --linked --skip-vault --yes`로 기존 16개 마이그레이션을 적용했다. 신규 마이그레이션은 만들지 않았다.
3. 누락된 테이블·컬럼 생성과 전체 41개 마이그레이션 반영을 확인했다. 운영 보안 advisor의 error 등급 지적은 없었다.
4. 원래 사용자가 확정한 기억 계획을 기존 `captureService.resolve`로 이어 처리했다. 재분류하거나 원문을 바꾸지 않았다.
5. 원문 유지, 활성 기억 1개, 확인 완료, 검색 인덱스 ready, 미처리 메모 0개를 검증했다. 같은 요청을 다시 실행해도 `changed=false`, 같은 기억을 반환했다.
6. 운영 DB에 대해 투데이 제안의 `refresh`와 `list`를 실행해 정상 완료를 확인했다. 제안이 없는 상태와 조회 실패를 구분했다.

## 코드·안내 개선

- 기억 확정·AI 재분류의 처리 실패를 구조화된 결과로 반환한다. 서버 로그에는 원인을 남기고, 화면에는 원문이 보관돼 있다는 사실과 재시도 경로를 표시한다.
- 확정 성공 시 수집함, 투데이, 기억, 할 일, 캘린더를 갱신한다.
- 분류 결과에 ‘제안’을 명시하고 ‘기억으로 저장’, ‘할 일로 추가’, ‘메모로 보관’처럼 목적지가 드러나는 버튼을 제공한다.
- 중단된 확정에는 ‘저장 확인 필요’와 중복 생성 없이 다시 확정할 수 있다는 안내를 표시한다.
- 분류 결과가 없을 때 실제 작업 상태를 확인하지 않고 ‘분류 대기’라고 단정하지 않는다. 원문 저장 상태와 ‘AI 분류’ 재요청 버튼을 제공한다.
- 빠른 메모의 기존 정책은 원문 저장 → AI 제안 → 사용자 확정이다. 자동 제안만으로 일정이나 장기 기억을 생성하지 않는다. 확정된 메모는 미처리 목록에서 빠지고, 원문은 처리 완료 목록에 남는다.
- 빌드 전에 앱이 의존하는 7개 테이블의 컬럼을 실제 Supabase Data API로 확인한다. HEAD 요청만 사용해 사용자 행을 읽지 않는다. 필수 구조가 없으면 앱 배포 빌드를 중단한다. 이 검사는 전체 마이그레이션 이력이나 모든 RPC를 대체하지 않는다.

## 검증

- 전체 Vitest: **321 통과 / 60 스킵**. 로컬 Supabase를 켠 상태에서 실행했다.
- 최종 수집함 집중 검사: **34 통과**. 서버 오류 결과, 폼 내용 보존, 중단된 기억 확정 재개·중복 방지·미처리 제외를 포함한다.
- DB pgTAP: **26 통과**. 운영 security advisor error 등급 지적 0개.
- TypeScript, 변경 파일 Biome, Next/Serwist 빌드 통과.
- DB 검사 자체는 구조 누락 응답에서 빌드를 실패시키고, 정상 응답에서는 통과하는 것을 검증했다.
- 실제 Luna에 가상의 선호 메모와 할 일을 입력해 `memory`, `task` 분류 및 `triaged` 저장을 확인했다. 사용자 원문을 분류 검증용으로 재전송하지 않았다.
- 390px Chromium: AI 기억 제안 확정 → 미처리 제외 → 처리 완료의 연결 링크 → 기억 화면 표시를 확인했다. 빠른 메모를 새로 입력하고 직접 기억으로 분류하는 경로도 같은 결과를 확인했다.
- 브라우저 검수용 로컬 사용자와 데이터는 삭제했다. 실제 iOS PWA에서의 확인은 포함하지 않았다.
